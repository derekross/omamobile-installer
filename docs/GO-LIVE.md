# Go-live checklist

What must pass, in order, before the installer reaches owners, and the switches that then make it reach them. Nothing here is switched on: no installer release is published, omamobile.org builds no installer page, and the server forbids WebUSB on every page.

Every run below is attended: the maintainer runs or approves each step at the keyboard, under Omarchy Mobile's AGENTS.md section 1, and records the result with its date, the installer commit and the release in the runbook's Results section. A run that stops is understood before the next one starts. No identifier goes into a result.

## 1. Attended runs, in order

| # | Run | Runbook | On | Passes when | Decides |
| --- | --- | --- | --- | --- | --- |
| 1 | **The command-line write path** (`omamobile-install install --write`): the release verified, the dry run against the phone, go or no-go, the write of slot B and `userdata`, the slot state after, what the phone shows | [WRITE-RUNBOOK.md](WRITE-RUNBOOK.md) steps 0 to 8; [app/docs/STATUS.md](../app/docs/STATUS.md) §6 part A | The reference Pixel 7 Pro, release 2026.11.14 or later (it must carry `factory-builds.json` and the answers' placeholders) | Every step's Pass, recorded in WRITE-RUNBOOK's Results | Maintainer (the write is the maintainer's go) |
| 2 | **The desktop app end to end**: read-only up to the confirmation (B1), then a reinstall from the write to a working phone, with the owner's answers and this computer's key in the image, the USB connection, the radio backup, the firmware, the restart and the check (B2). Run from the packages this workflow builds (`.github/workflows/release.yml`, a run by hand), not from a checkout | [app/docs/STATUS.md](../app/docs/STATUS.md) §6 parts B1 and B2 | The same phone, release 2026.11.14 or later; the Arch package on Omarchy, and the AppImage once on another distribution (read-only up to the confirmation is enough there) | B1 and B2 recorded as passed; the phone works afterwards (`tools/phone-smoke`) | Maintainer |
| 3 | **The web page in a real browser**: the shipping page's download of the real release from `pkgs.omamobile.org`, its look at the phone and its dry run, read-only | [WEB-WRITE.md](WEB-WRITE.md) §8 steps 0 to 6 (and 7 once reachable) | Chromium on Linux, with the page served with `Permissions-Policy: usb=(self)` (the release workflow's `omamobile-installer-web-*.tar.gz`, served locally) | Every step's Pass, recorded in WEB-WRITE §9 | Maintainer |
| 4 | **The install link, R0 to R8**, which the web page needs for the firmware: a browser can't run the release's own tools, so on the web the firmware comes over the link | Omarchy Mobile's [INSTALL-LINK-PLAN.md](https://github.com/derekross/omarchy-mobile/blob/main/docs/INSTALL-LINK-PLAN.md) §11.2; STATUS §6 part D | The reference phone, a release whose `manifest.json` has `install_link` | R0 to R8 recorded as passed (R9 and R10 before any release carries the link's marker) | Maintainer (R7 and R8 write slot B and `userdata`) |
| 5 | **The slot probe, for first installs**: a first install on a phone that runs from slot A measures the other bootloader slot instead of asking the owner for its version | [WRITE-RUNBOOK.md](WRITE-RUNBOOK.md) "A first install that measures the other slot" (P0 to P5), on `first-install-slot-probe` (#19) until it is merged | The reference Pixel 7 Pro, with stock Android put back on slot A first (P0, the owner's own flash; a fresh radio backup after it) | Every step recorded as passed, slot A put back as it was | Maintainer |

Runs 1 and 2 gate the desktop app. Runs 3 and 4 gate the web page, and run 3 needs run 1 first. Run 5 gates first installs in both: until it passes, the app and the page reinstall a phone already on Omarchy Mobile and stop a first install at the bootloader-slot stop, as they do today, and the download pages say so.

The web page as it ships ends at the dry run and can't write. Letting a browser write a phone is a separate decision of the maintainer's (WEB-WRITE §7 and §8, DESIGN §2): it changes `tools/check-shipping` in its own pull request and is not one of the switches below.

## 2. The switches, in order

| # | Switch | Where | How it is flipped | Undo | Decides |
| --- | --- | --- | --- | --- | --- |
| 1 | The installer branches on `main`: `installer-next` (#18), then `first-install-slot-probe` (#19) and `release-artifacts` | This repository | Merge the pull requests | Revert | Maintainer |
| 2 | **The first tagged installer release** | This repository: `.github/workflows/release.yml` | Set `pkgver` in `app/pkgbuild/PKGBUILD` and `VERSION` in `app/omainstall.pro` to the version (the workflow refuses a tag that differs), tag `vX.Y.Z` on `main` and push the tag. The workflow builds the Arch package, the AppImage and the web page's archive, with `SHA256SUMS`, and makes a **draft** release. The maintainer compares the sums with the run's artifacts, then publishes the draft | Unpublish or delete the release; a published file is never replaced, a fix is a new version | Maintainer |
| 3 | **The header**: `Permissions-Policy: usb=(self)` on `omamobile.org/install/web/app/` only | The server's nginx; prepared in derekross/omamobile-website, `deploy/nginx/` and `docs/INSTALLER-WEB.md` | By hand on the server, with sudo: the snippet, the location block, `nginx -t`, a verified reload, then `curl -sI` on that path (`usb=(self)`) and on `/` (still `usb=()`) | Restore the vhost's backup, `nginx -t`, verified reload | Maintainer (the server's admin) |
| 4 | **The website flag**: `INSTALLER_WEB=on`, the release tag and the web archive's SHA-256 | derekross/omamobile-website, `installer-web.env` | A pull request there; merging deploys. The deploy downloads the archive from the published release, refuses it unless its SHA-256 is the pinned one, and builds the draft page `/install/web/` (not in the navigation, `noindex`) | `INSTALLER_WEB=off` in a pull request; the next deploy removes the files | Maintainer |
| 5 | **Telling people**: the site's navigation and the main README's install section pointing to `/install/web/` and to [INSTALL-APP.md](INSTALL-APP.md); `noindex` off; an announcement | derekross/omamobile-website, derekross/omarchy-mobile | Pull requests | Revert | Maintainer |

Switch 3 is safe before switch 4: the path answers 404 until the files are there. Switch 4 before switch 3 is safe too: the page loads, the browser refuses it WebUSB, and the deploy's log warns. Neither lets a browser write a phone: the page that ships can't.
